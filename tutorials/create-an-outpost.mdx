Use the setup wizard when you need a new outpost. It can configure
Modal, create the outpost, store the Devin token, generate the application, and
deploy it.

In Devin's terminology, an [outpost is a named queue of
sessions](https://docs.devin.ai/cloud/outposts/overview#2-create-an-outpost) served by
your infrastructure. This workflow creates that queue in Devin and deploys its
orchestrator to Modal. It does not run the orchestrator or a worker on your local
machine.

## Before you begin

You need Python 3.11 or newer, a [Modal
account](https://modal.com/docs/guide/modal-user-account-setup), and a Devin
organization with Outposts enabled. Outposts is early access; contact your Cognition
account team if it is unavailable.

Install the package:

```bash
uv add modal-devin
```

## Create a Devin service user token

The orchestrator and workers authenticate with a Devin v3 API token belonging to a
service user. In the Devin web app:

1. Open **Settings → Roles** and create an enterprise role.
2. Under **Outpost permissions**, enable **Use outpost machine**
   (`UseOutpostsMachine`) and **Manage outposts** (`ManageOutpostsOrchestrator`).
3. Open **Settings → Devin API → Service users**, provision a service user with that
   role, and choose an expiration.
4. Copy the `cog_...` token when it appears. Devin displays it only once.

These permissions grant `account.outposts.machine` and
`account.outposts.orchestrator`. The latter is required for the wizard to create the
outpost. See Devin's [Outposts quickstart and permission
definitions](https://docs.devin.ai/cloud/outposts/overview#1-create-a-service-user-token).

<Note>
  Use this scoped role rather than an administrator role. The generated application
  needs Outposts access, not general Devin administration permissions.
</Note>

The wizard runs without a local Devin CLI because `init` creates the outpost through
the Devin Outposts API.

<Steps>
  <Step title="Start the wizard">
    ```bash
    uv run modal-devin init
    ```
  </Step>

  <Step title="Configure Modal if prompted">
    When local credentials are missing, accept **Set up Modal now?** to launch
    `modal setup`.
  </Step>

  <Step title="Name the deployment">
    Choose a durable name that describes the outpost's role, such as
    `frontend-production` or `gpu-builds`. The wizard uses it for the outpost,
    generated filename, and Modal resources.
  </Step>

  <Step title="Provide the Devin token">
    Paste the `cog_...` service user token. The wizard uses it to create the outpost
    and offers to store it as a Modal Secret. Input is hidden, and the generated
    application excludes the token.
  </Step>

  <Step title="Deploy">
    Accept **Deploy now?** or deploy the generated file later:

    ```bash
    uv run modal-devin deploy outposts/<generated_name>.py
    ```
  </Step>

  <Step title="Start a session in Devin">
    In Devin Cloud, start a new session and select the new outpost as its machine.
    Devin queues the session; the Modal orchestrator claims it and starts a worker in
    a new Sandbox.
  </Step>
</Steps>

## If setup fails

The wizard avoids overwriting existing files and reports any remote resource that
may need cleanup. Follow the printed recovery step, then rerun the command after the
underlying problem is fixed.

## Automate setup

For non-interactive use, provide a name and an existing outpost ID:

```bash
uv run modal-devin init ci-outpost \
  --outpost-id outpost_env-... \
  --secret-name ci-devin-token \
  --outposts-dir deployments \
  --no-deploy
```

When `--outpost-id` is omitted, `init` creates a new outpost by calling the Devin
Outposts API directly. In a non-interactive environment, make sure
`DEVIN_OUTPOSTS_TOKEN` is set so the request can be authorized.

See the complete [`init` option reference](/reference/cli#modal-devin-init).
